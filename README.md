# ETCH Element Cards — Landing Page

Sales landing page for ETCH Element Cards. Standalone from the Shopify store, built for Instagram ad traffic. Mobile-first, vanilla HTML + CSS + ES modules, no build step.

## Quick start

```bash
npm install
npm run dev              # static server on http://localhost:3000 (scripts/serve.cjs, loopback only)
```

## Testing

```bash
npm test                                   # unit tests (Vitest + jsdom)
npm run test:e2e                           # E2E (Playwright: mobile + desktop, axe audit, links, assets, meta)
BASE_URL=https://example.org/ npx playwright test   # same E2E suite against a deployed URL
```

The E2E fixture blocks Google Fonts so slow font downloads cannot time out functional tests; scripts that need the real typefaces (OG image) do not use it.

## Configuration

Everything that changes between environments or business stages lives in [`js/config.js`](js/config.js):

| Key | Purpose |
|---|---|
| `canonicalUrl` | Public URL. Also appears in the `<head>` canonical / `og:url` / `og:image` / `twitter:image` tags — keep both in sync. |
| `instagramHandle`, `contactEmail` | Social handle (DM + profile links) and contact mailbox. Both unconfirmed at the time of writing. |
| `orderPath` | `"instagram"` (interim: SELECT opens an Instagram DM and copies a bilingual order message to the clipboard) or `"shopify"` (SELECT opens each product's `shopifyUrl`; products without one fall back to the DM). |
| `metaPixelId`, `ga4Id` | Empty strings load no tracking at all. When set, the page reports ViewContent, InitiateCheckout (product, value, HKD) and Contact. |
| `products` | Names, prices and (future) Shopify URLs for the four pricing cards. |

## Architecture

- **CSS:** modular files imported via `css/main.css`; design tokens in `css/tokens.css` (`--gold-deep` is for small gold text on light backgrounds, which plain gold fails for contrast).
- **JS:** one module per concern — `config`, `links`, `order`, `analytics`, `smooth-scroll`, `scroll-observer`, `element-scroll`, `element-tabs`, `faq-accordion`, `sticky-nav` — wired in `js/main.js`.
- **Section 3:** each element stage is 170vh with sticky background, overlay and text layers driven by scroll progress. The stage uses `overflow: clip`; `overflow: hidden` would turn it into a scroll container and silently disable the pinning.
- **Images:** element backgrounds are WebP + progressive JPEG + 32 px JPEG LQIP, generated by `py scripts/build-images.py` from the masters in `design/handoffs/claude-design-v2/landing-page/project/assets/`. The hero card and craft macro are inline SVG interim visuals that render with the page's real typefaces.
- **OG image:** `node scripts/build-og-image.cjs` renders the live hero at 1200×630 into `assets/og-image.jpg`. Re-run after any hero change.

## Deploy (GitHub Pages)

The public repo `siusiutinonfire-ui/etch-landing` contains only this folder, served from its `main` branch at `/` (`.nojekyll` is present). From the repository root:

```bash
git subtree push --prefix landing-page https://github.com/siusiutinonfire-ui/etch-landing.git main
```

Live URL: https://siusiutinonfire-ui.github.io/etch-landing/ — verify with `BASE_URL=https://siusiutinonfire-ui.github.io/etch-landing/ npx playwright test`.
